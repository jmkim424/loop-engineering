주요 사례를 바탕으로 루프 엔지니어링 분해 해보기 
1. 오래된 문서 최신화 루프
문제 상황 : 위키가 있으나, 그 위키 내용이 최신화 되지 않고 방치되는 경우가 생긴다. 

- 시작 조건 : 3달 지난 문서가 존재하는 시점에 (매일 아침 9시에 크론잡으로 문서 정렬후 검색)
- 루프 목표 : 문서의 내용을 현재와 대조해서, 보관/이동/최신화를 결정한다.
                   (코드베이스, 공백으로 두기, 질문하기) 
- 완료 조건 : 뭐든 결론이 난다. (보관/이동/최신화 결정이 내려지고 실행된다.) 
- 중단 조건 : 공지사항 문서/아카이빙 문서와 같이 수정되면 안되는 내용들이다. 

현재 우리 백엔드 코드베이스는 이러하다, 이런 문서가 있으면 AI가 문서를 읽고 목적을 백엔드, 코드베이스 설명 문서로 정리해서 관련된 맥락을 가지고 오고 수정한다. 


2. 대규모 코드 베이스 리팩토링
문제상황 : Java8 기반으로 된 서비스를 자바 27로 올리면서 성능개선+동시실행 등등 실행 가능하게 해야함

루프를 여러번 설계
1) 현재 코드베이스를 분석해서 리팩토링 포인트를 찾는 에이전트 팀을 루프처럼 돌리기.
 (각 도메인마다 똑같은 Opus 2개 호출해서..)
2) 현재 코드 베이스를 기준으로 100% 성공하는 테스트 코드 작성하는 루프 (각 도메인 마다) 
 (함수 하나가 있다면 그 함수 동작이 100% 일치한다고 입증하기 위함)
3) 리팩토링 포인트 + 테스트 코드를 바탕으로 멱등성이 보장 되었기에 리팩토링 + 테스트 + 회귀를 하는 그런걸 돌리는 루프 만들기 였다.
